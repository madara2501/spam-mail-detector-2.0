# Spam Detector 2.0 — Assignment 02

## Objective
Extend a basic spam/ham text classifier to detect **Phishing**, return a confidence score, and provide a short human-readable explanation through a Flask `/predict` endpoint.

## Implementation
- 3 classes: `ham`, `spam`, `phishing`
- TF-IDF unigrams + bigrams
- Logistic Regression
- Stratified 80/20 train-test split
- Training-only TF-IDF fitting to avoid leakage
- Confidence via `predict_proba`
- Top contributing TF-IDF terms for explanation
- `POST /predict`
- `GET /health`
- Basic JSON/input validation

## Dataset
Original SMS Spam Collection data was retained. Because the supplied dataset contains only ham/spam labels, 20 project-created phishing examples were added for the new class. This is explicitly documented rather than presented as original labeled data.

Class counts (verified from the actual `spam.csv` used to train the shipped model):
```
ham         4825
spam         747
phishing      20
```

## Held-out test metrics
These numbers are written automatically by `train_model.py` into `metrics.json` on every run, so they can never drift out of sync with the model actually shipped in this folder.

Accuracy: **0.9750**
Weighted Precision: **0.9769**
Weighted Recall: **0.9750**
Weighted F1: **0.9755**

Confusion matrix labels: `[ham, spam, phishing]`

```text
[[944  22   0]
 [  5 144   0]
 [  1   0   3]]
```

The phishing class only has 4 held-out test examples (20 total examples, 80/20 split), so its precision/recall numbers are noisy — this is a known limitation of the small hand-authored phishing set, not a bug. Given more time, the honest next step would be adding more phishing examples rather than trusting these numbers.

## Run locally
```bash
pip install -r requirements.txt
python train_model.py
python app.py
```

The API runs on port 5000.

### Health
`GET /health`

Expected:
```json
{
  "service": "spam-detector-2.0",
  "status": "healthy"
}
```

### Predict
`POST /predict`

Request:
```json
{"message":"Your account is locked. Verify your password and OTP immediately."}
```

Response shape:
```json
{
  "class": "phishing",
  "confidence": 0.9952,
  "explanation": "The prediction was influenced mainly by: verify, account, otp."
}
```

See `examples.json` for real outputs, generated by actually calling the running API (via `generate_examples.py`) rather than hand-written/estimated values.

## Bug fixed in this pass
The web UI (`GET /`) was returning a 500 Internal Server Error. `app.py` calls
`render_template("index.html")`, which requires Flask's default template
folder (`templates/`) — but `index.html` had been placed at the project root
instead. Reproduced with a plain `curl http://127.0.0.1:5000/` (confirmed
`jinja2.exceptions.TemplateNotFound: index.html` in the server log), fixed by
moving the file to `templates/index.html`. Verified after the fix: `GET /`
now returns 200 with the full page. `/predict` and `/health` were already
working correctly, including validation for missing/empty/non-string
messages and malformed JSON.

Separately, `examples.json` and `metrics.json` in the original upload did not
match the actual output of the shipped `model.pkl`/`vectorizer.pkl` (correct
predicted classes, but wrong confidence values and word lists) — likely
leftover from an earlier training run that was never re-verified. Fixed by:
regenerating `metrics.json` automatically inside `train_model.py` on every
run, and adding `generate_examples.py` to produce `examples.json` from real
API calls instead of transcribing numbers by hand.

## Scope decision
The requested 3-class version was implemented while keeping the API intentionally small. No unnecessary authentication, database, frontend framework, or deep-learning model was added because the assignment prioritizes a working, clearly scoped feature within the time limit.
